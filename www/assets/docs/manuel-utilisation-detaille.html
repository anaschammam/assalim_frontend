Annexe A

À propos de ce document

Comment lire le manuel approfondi et l’aligner sur l’application

Objectif

Ce manuel est destiné aux personnes qui configurent l’outil, forment les équipes ou ont besoin de comprendre chaque étape d’un écran (champs obligatoires, ordre des calculs, messages d’erreur typiques). Le manuel d’utilisation (synthèse) reste la porte d’entrée ; ici nous descendons au niveau procédure + justification métier.

Méthode de lecture

  • Prérequis : droits utilisateur, données déjà créées (ex. client, produit), session de caisse si le parcours l’exige.
  • Étapes numérotées : à suivre dans l’ordre sauf mention contraire.
  • Figures : les captures du dossier manual-screenshots/ sont partagées avec le manuel synthèse ; des captures supplémentaires pourront être ajoutées dans manual-screenshots-detail/ (préfixe libre, ex. d-pos-remise.png) puis référencées ici.
  • Écarts de version : en cas de mise à jour mineure de l’interface, le texte peut légèrement devancer ou retarder l’UI — le comportement décrit est celui du code applicatif au moment de la rédaction.
Maintenance
Quand un écran change (libellé, emplacement d’un bouton, nouveau champ), mettez à jour d’abord le manuel synthèse si l’utilisateur lambda est impacté, puis ce manuel approfondi pour les parcours détaillés concernés.
Annexe B

Connexion, session et navigation

Depuis l’URL jusqu’au module — avec points de vigilance

B.1 Connexion

1

URL et contexte

Saisissez l’adresse fournie par votre administrateur (instance cloud ou serveur interne). Vérifiez le cadenas HTTPS en production.

2

Identifiants

Sur un poste déjà utilisé : touchez un profil mémorisé, puis PIN caisse (si défini) ou mot de passe. Sinon e-mail et mot de passe. En cas d’échec répété, un verrouillage temporaire peut s’appliquer selon la politique de sécurité.

3

Première connexion / mot de passe oublié

Suivez le flux « mot de passe oublié » du manuel synthèse ; notez les délais d’expiration des liens s’ils sont affichés dans l’email.

B.2 Coque de l’application (barre latérale, hub, aide)

  • Menu latéral : regroupe les modules selon vos permissions — une entrée absente signifie souvent un rôle insuffisant, pas un bug.
  • Hub : raccourcis visuels ; utile sur tablette ou pour les profils qui n’utilisent que quelques briques.
  • Menu Aide (?) : visite guidée, manuel synthèse, manuel approfondi, navigation rapide.
  • Langue et thème : français, anglais ou arabe (RTL) ; thème clair / sombre / système — persistés sur l'appareil.
  • Modes verrouillés : menu compte → mode caissier (POS + caisse) ou serveur (salle). Sortie = mot de passe gérant. Distinct du kiosque (plein écran sans PIN) et du verrou caisse PIN pendant une session POS (annexe D.8).

B.3 Licence, abonnement et messages bloquants

Si l’instance affiche un bandeau ou un écran de blocage (licence expirée, abonnement requis), les modules métier peuvent être inaccessibles. Consignez pour les utilisateurs : qui contacter (admin interne vs éditeur), et quelles opérations d’urgence restent possibles (ex. consultation seule).

Annexe C

Référentiels (produits, clients, fournisseurs, unités)

Qualité des données en amont du POS et des documents

Les écrans de référentiel déterminent ce qui apparaît au POS (prix, code-barres, stock, image, vente au poids) et sur les documents (TVA, remises autorisées côté métier, conditions de paiement).

C.1 Produits

  • Création / modification : nom, codes-barres principal et secondaire, catégorie, unité, prix d’achat HT, prix de vente TTC, TVA, stock minimum, photo.
  • Étiquettes : A4 (une étiquette 50×30 mm par unité de stock vendable de la page) ou rouleau unitaire depuis la liste / la fiche. Option « Prix sur les étiquettes » dans les paramètres généraux.
  • Un article inactif n’apparaît plus dans la recherche POS. Les seuils de stock alimentent les alertes (§H).

C.2 Clients et fournisseurs

  • Fiche tiers : identifiants fiscaux, plafond de crédit, conditions de paiement par défaut.
  • Association aux documents et conséquence sur les échéances et relances.

C.3 Unités et catégories

Harmoniser les unités avant les imports massifs ou l’usage POS évite les erreurs de quantité et d’arrondi sur les inventaires.

Annexe D

POS vente — parcours complet

Du ticket au pavé Encaisser, y compris remises et totaux

Un seul écran tactile (vente et achat) : tuiles catalogue, ticket, pavé. Il n’y a plus de caisse à quatre colonnes. Le POS vente calcule les montants dans un ordre précis : chaque ligne a un montant de base (quantité × prix catalogue ou prix chargé depuis un document), puis des ajustements (remise ligne ou prix unitaire forcé). Le sous-total du ticket est la somme des totaux de ligne déjà ajustés. Une remise globale s’applique ensuite sur ce sous-total (pourcentage, montant fixe, ou total imposé).

Vue d’ensemble : tuiles catalogue, ticket, pavé Encaisser.

D.0 Déroulement type d’une vente

1

Session de caisse

Sans session ouverte, le POS peut vous rediriger vers l’ouverture de caisse (voir chapitre Caisse du manuel synthèse).

2

Ajout au ticket

Toucher une tuile ou scanner le code-barres ; la ligne apparaît avec quantité modifiable.

3

Client (optionnel mais recommandé)

Associer le client pour l’historique, le crédit et les conditions de paiement par défaut.

4

Remises et ajustements

Voir sections D.1 et D.2 ci-dessous.

5

Encaisser

Moyen de paiement sur le pavé, montant reçu (ou Exact), rendu monnaie si espèces ; Encaisser crée le document de vente attendu.

D.1 Remises par ligne et remise globale

Ouvrir les contrôles de remise sur une ligne

  • Sur le ticket, touchez la ligne puis le chip remise ou le mode Remise du pavé. Les contrôles s’affichent.
  • Le montant de base de la ligne peut apparaître barré pour rappeler le catalogue avant remise.

Types de remise sur une ligne

TypeSaisieEffet
Aucun—Prix catalogue (ou prix issu du document chargé) × quantité.
Pourcentage0 à 100 % (pas à l’unité décimale près pour le pourcentage)Réduction (ou majoration si votre saisie le permet) calculée sur le montant de base de la ligne.
Montant fixeMontant en devise, plafonné au montant de base de la ligneRéduit d’un montant absolu la ligne.
Prix unitaire forcéNouveau prix unitaire (minimum 0,01)Fixe directement le prix unitaire ; utile pour une négociation ponctuelle sans passer par un pourcentage.
Référence prix d’achat
Si la fiche produit contient un prix d’achat, le POS peut afficher un rappel sur la ligne. Si le prix de vente effectif passe sous le prix d’achat, un avertissement visuel (couleur, icône) signale une marge négative — la vente peut toutefois être autorisée selon vos règles métier.

Supprimer une remise ligne

Utilisez le bouton de suppression de remise (icône proche des champs de remise) pour revenir au calcul catalogue sur cette ligne.

Totaux affichés en bas du ticket

  • Sous-total de base : somme des montants catalogue (hors remises ligne), en tenant compte des quantités et des retours éventuels.
  • Sous-total : somme des totaux de ligne après remises (c’est la base sur laquelle s’exprime la remise globale en pourcentage).
  • Remise appliquée (ligne rouge) : récapitulatif textuel de la remise globale lorsqu’elle est active.

Remise globale (bas du ticket, sans ligne sélectionnée)

TypeSaisieEffet sur le total à payer
Aucune—Pas de remise globale ; un ancien champ « remise en montant » peut encore apparaître si aucun type moderne n’est choisi (comportement de compatibilité).
Pourcentage0 à 100 %Le total devient sous-total × (1 − %/100).
Montant fixeMontant ≤ sous-totalLe total devient sous-total − montant.
Forcer le totalMontant TTC cible > 0Le total à payer devient exactement ce montant (arrondi commercial selon les règles de l’application).
Ordre à retenir pour la formation
1) Remises / prix sur chaque ligne → 2) remise globale (ou total forcé) sur le sous-total déjà remisé.

D.2 Mode rapide et visibilité des remises

En mode rapide (fast mode), le ticket tactile masque le chip remise, le mode Remise du pavé et les détails « base / remise » pour accélérer l’encaissement standard. Si un utilisateur applique une remise globale alors que le mode rapide était actif, l’application désactive le mode rapide et affiche un message d’information pour éviter une incohérence silencieuse.

Piège fréquent
Si un caissier « ne voit pas » les remises, vérifier d’abord le mode rapide avant d’ouvrir un ticket support.

D.3 Conversion documentaire et quantité source

Lorsque le POS est ouvert en conversion (ex. commande → facture), chaque ligne peut afficher la quantité source du document d’origine sous le sélecteur de quantité. Vous modifiez la quantité sur le nouveau document tout en gardant la référence visible.

D.4 HoReCa : lignes annulées en cuisine → facture

Une ligne marquée annulée en cuisine peut porter une quantité à facturer proposée à 0 lors de la conversion en facture depuis le POS, avec pastille de statut. La quantité source du document reste visible pour audit.

D.5 Scan GS1 DataMatrix et affiche client

Le champ scan du POS parse un DataMatrix GS1 (GTIN, lot, DLC) via parseGs1Barcode puis interroge le produit par GTIN. Un EAN-13 simple reste inchangé. L'affiche client (/pos/customer-display) synchronise le panier via un canal navigateur : l'ouvrir depuis la barre d'actions POS sur un second écran. Pas de POS embarqué dans l'app manager /m.

D.6 Filtre En stock

Bouton En stock à côté de la recherche catalogue. Visible seulement si la gestion de stock est activée. Actif par défaut à l’ouverture de la caisse vente. L’API liste / recherche / catégorie envoie inStock=true (stock vendable > 0). Les favoris sont filtrés côté client. Un scan code-barres n’est pas filtré. POS achat : bouton À commander, éteint par défaut.

D.7 Client, solde, fidélité, tarifs

Surfaces verrouillées (pas d’interrupteur dans pos_ui_options) : entity toujours visible ; entityCredit, loyalty, commercialPricing selon le tiers / les prix appliqués. L’UI POS masque solde et fidélité tant qu’aucun tiers n’est choisi. Fidélité et tarifs = vente seulement. Achat : solde fournisseur si crédit fournisseur actif.

D.8 Verrou caisse (PIN)

Bouton Verrouiller la caisse du bandeau (pas le ticket). Overlay visages + PIN. Inactivité : paramètre staff_lock_idle_seconds (défaut 90, 0 = jamais). Distinct du mode caissier verrouillé (mot de passe gérant, §B.2).

D.9 Paiement mixte, rupture et droit de timbre

  • Paiement mixte : plusieurs moyens sur la même vente ; le total des parts doit couvrir le dû. Toucher une ligne la sélectionne (pavé Reçu). + Espèces / + Carte / + Chèque ajoute une part.
  • Rupture : tuile et ligne marquée ; l’ajout n’est pas bloqué ; l’encaissement demande confirmation.
  • Droit de timbre : taux % par mode (paramètres généraux) sur la part encaissée, hors CA, comme le pourboire. Visible sur ticket, paiement, avance et clôture (part espèces).

Annexe H

Stock et inventaires

Mouvements, inventaire physique, alertes

Si la gestion de stock est désactivée pour l’instance, les modules Stock / Inventaire sont masqués et le POS n’envoie plus le filtre En stock. Les ventes ne décrémentent pas le stock.

H.1 Sites / dépôts et transferts

Un tenant a au moins un site défaut (POS). Les ventes et le POS débitent uniquement ce site. Créer un dépôt : /stock/sites. Déplacer du stock : /stock/transfers — confirmation atomique (sortie source + entrée destination). Refus si quantité vendable insuffisante. WhatsApp n'est pas utilisé ici ; le partage WhatsApp concerne factures, résas et propositions d'achat.

Annexe K

HoReCa — Restaurant / Café

Plan de salle, sessions table, cuisine (KDS), réservations, statistiques salle, appel serveur (QR)

K.1 Vue d'ensemble

Le module HoReCa (Hotel, Restaurant, Café) permet de gérer l'intégralité du service en salle : plan de salle interactif, sessions par table, écran cuisine (KDS), calendrier de réservations et statistiques détaillées.

Flux standard : Ouverture de session → Ajout d'articles → Envoi en cuisine → Suivi KDS → Demande d'addition → Encaissement POS.

K.2 Plan de salle

Accès : menu Plan de salle. Le plan se rafraîchit automatiquement toutes les 30 secondes.

  • Couleurs des tables : vert = libre, orange = occupée, rouge = addition demandée, gris = nettoyage requis.
  • Minuteur d'occupation : durée de la session en cours affichée sur la carte.
  • Zoom : molette souris (Ctrl+défilement), boutons +/− en bas à droite, ou pincement tactile.
  • Nouvelle commande comptoir : bouton « Comptoir » → choisir Emporter ou Livraison pour ouvrir une session sans table assignée (/horeca/comptoir).
  • Appels serveur : cloche en haut à droite avec badge rouge ; panneau latéral listant les appels en attente ; badge pulsant sur la carte de la table concernée.
  • QR code par table : survolez une carte de table → icône QR → dialogue avec code imprimable et lien /call/{token}.

K.3 Session table

Cliquez sur une table libre pour l'ouvrir. Un dialogue vous demande le mode de service (sur place / emporter / livraison) et le nombre de couverts.

  • Ajout d'articles : utilisez la barre de recherche ou naviguez par onglets de catégories (style POS).
  • Modificateurs : les options personnalisables apparaissent lors de l'ajout (cuisson, allergènes…).
  • Envoi en cuisine : bouton « Envoyer en cuisine » — les lignes PENDING partent vers le KDS.
  • Demande d'addition : le statut de la table passe à « Addition demandée » et pulse sur le plan.
  • Partager l'addition : bouton « Partager l'addition » pour répartir les articles en deux parts, puis encaisser chaque part séparément dans le POS.
  • Encaissement : bouton « Encaisser » ouvre directement le POS avec la commande pré-remplie.

K.4 Écran cuisine (KDS)

Accès : menu Cuisine (KDS). L'écran KDS affiche les commandes envoyées, triées par station de cuisine.

  • Statuts : En attente → En préparation → Prêt → Servi.
  • Chronomètre : temps écoulé depuis l'envoi, affiché sur chaque carte (format MM:SS).
  • Annuler en cuisine : annule la ligne avec confirmation (refus de préparation).
  • Rupture de stock : bouton « Rupture » pour signaler un article indisponible ; la ligne passe en statut Rupture.
  • Mode TV plein écran : bouton TV pour afficher le KDS sans la navigation principale.

K.5 Calendrier des réservations

Accès : menu Réservations. Vue hebdomadaire avec un créneau par heure.

  • Créer une réservation : remplissez le formulaire (date, heure, table, couverts, nom, téléphone) et cliquez « Enregistrer ».
  • Filtres : filtrer par table et par statut (Réservée / Installée / Annulée / Non venue).
  • Actions rapides : marquer comme « Installé(e) », annuler ou supprimer depuis la carte de réservation.
  • Navigation : boutons ← Semaine précédente / Aujourd'hui / Semaine suivante →.

K.6 Statistiques salle

Accès : menu Statistiques salle ou via le hub Rapports.

  • KPIs globaux : CA total, nombre de sessions, moyenne couverts, durée moyenne de session, taux de rotation.
  • Heatmap horaire : histogramme du CA par tranche horaire pour identifier les heures de pointe.
  • Performance par table : classement des tables par CA, avec sessions, couverts moyens, durée et taux de rotation.
  • CA par serveur : classement des serveurs (utilisateurs) par chiffre d'affaires et nombre de sessions.
  • Période : 7 j / 30 j / 90 j ou dates personnalisées.
  • Export PDF : bouton « Exporter PDF » → impression via la boîte de dialogue du navigateur.

K.8 Appel serveur (QR code / tablette cliente)

Chaque table possède un jeton unique permettant aux clients d'appeler un serveur depuis leur téléphone, sans compte ni application.

Côté personnel — mise en place

  1. Allez sur Plan de salle (/horeca/salle).
  2. Survolez une table → cliquez l'icône QR code.
  3. Imprimez le QR (bouton « Imprimer ») et placez-le sur la table, ou copiez le lien.
  4. Le lien a la forme https://votre-domaine/call/{token}.

Côté client — utilisation

  1. Le client scanne le QR code avec l'appareil photo de son téléphone.
  2. Une page s'ouvre avec le nom de la table et un bouton « Appeler le serveur ».
  3. Il peut ajouter un message optionnel (ex. « Eau s'il vous plaît »).
  4. Un seul appel actif par table à la fois ; un second appel affiche « Serveur en route ».

Côté personnel — traitement

  • La cloche du plan de salle affiche le nombre d'appels en attente (rafraîchissement toutes les 15 s).
  • Cliquez la cloche pour ouvrir le panneau ; acquittez chaque appel individuellement ou « Tout acquitter ».
  • La carte de la table affiche un badge rouge pulsant tant que l'appel n'est pas traité.
⚠️ Test en développement
La page /call/{token} est publique (sans connexion). Pour la tester localement, utilisez une fenêtre de navigation privée ou videz le jeton stocké dans le navigateur, afin d'éviter une redirection vers la page de connexion.

Renouveler un QR code

Si un QR code est compromis ou doit être remplacé, un administrateur peut régénérer le jeton via l'API POST /api/horeca/tables/{id}/call-token/regenerate. Les anciens QR codes deviennent alors invalides.

K.9 Board livraisons (téléphone / Glovo / Uber)

Écran /horeca/livraisons. Saisie manuelle uniquement (pas d'API partenaire). Canaux extensibles : PHONE (téléphone requis), GLOVO / UBER_EATS (n° plateforme requis), OTHER. Statuts : Reçue → En prép. → Prête → En route → Livrée. Envoi KDS seulement si au moins une ligne cuisine. WhatsApp si canal téléphone + n°.

M.1 Sauvegarde & restauration base de données

Accès : Paramètres → Backup base de données (/settings/backup). Réservé au rôle Administrateur.

Télécharger un backup

  1. Ouvrez la page Backup depuis les liens en bas de l'écran Paramètres.
  2. Saisissez un mot de passe, puis cliquez « Télécharger le backup » — un fichier chiffré .assalim.bak est généré via pg_dump.
  3. Conservez ce fichier dans un emplacement sécurisé (cloud chiffré, disque externe…).

Restaurer depuis un backup

⚠️ Opération destructive
La restauration écrase entièrement la base de données actuelle. Téléchargez toujours un backup récent avant de procéder.
  1. Sélectionnez un fichier .assalim.bak (ou un ancien .sql) et saisissez le mot de passe.
  2. Tapez exactement RESTAURER dans le champ de confirmation.
  3. Cliquez « Restaurer la base » et redémarrez le serveur après la fin de l'opération.

Prérequis serveur : les utilitaires pg_dump et psql doivent être installés et accessibles sur la machine hébergeant le backend (variable optionnelle pg.tools.path).
